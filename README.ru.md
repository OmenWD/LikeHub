# LikeHub — интеграция для Home Assistant

*[English version](README.md)*

Агент облачного сервиса внутри Home Assistant: передаёт аварии, телеметрию и heartbeat, принимает и исполняет команды из кабинета LikeHub. Только исходящие HTTPS-соединения — порты открывать не нужно, входящих подключений и HTTP-обработчиков интеграция не создаёт.

## Требования

- Home Assistant 2025.1 или новее
- Любой тип установки: HA OS, Supervised, Container, Core
- Исходящий доступ к `https://api.likehub.me` по 443 порту

Внешних зависимостей нет: `manifest.json → requirements` пуст.

## Установка

1. Завести учётную запись на [likehub.me/crm/](https://likehub.me/crm/) — вкладка «Регистрация» на экране входа. Вместе с аккаунтом создаётся первый объект.
2. HACS → ⋮ → **Custom repositories** → добавить `https://github.com/OmenWD/LikeHub`, тип `Integration`.
3. Найти **LikeHub** в HACS, скачать последний релиз и **перезапустить Home Assistant**.
4. Настройки → Устройства и службы → **Добавить интеграцию** → **LikeHub**.
5. Ввести почту и пароль учётной записи. Адрес сервера уже заполнен: `https://api.likehub.me`.

Пароль используется один раз для получения токенов и **не сохраняется**: в записи хранится только refresh-токен. При смене пароля Home Assistant покажет «Требуется повторная авторизация» — достаточно ввести новый, настройки объекта сохранятся.

Если к аккаунту привязано несколько объектов, появится шаг «Выбор объекта» — выберите тот, который обслуживает эта установка.

Установка без HACS: скопировать `custom_components/likehub/` из релиза в `config/custom_components/`, перезапустить и продолжить с шага 4.

## Настройка

Настройки → Устройства и службы → вкладка «Интеграции» → карточка **LikeHub** → у записи объекта **Настроить**. Прямая ссылка: `/config/integrations/integration/likehub`.

Открывается меню из трёх разделов.

### Передаваемые устройства

Пока здесь ничего не выбрано, наружу не уходит ничего — это единственный раздел, который обязательно заполнить.

Раздел открывается таблицей передаваемого — устройство, сколько параметров и какие именно, — а под ней тот же список отметками. **Снятая отметка и есть удаление**: устройство перестаёт передаваться, само оно и его сущности в Home Assistant остаются на месте. Сущности без устройства (помощники, шаблонные датчики) стоят отдельными строками.

Две отметки ведут дальше:

- **Добавить устройство** — выбрать устройство, затем отметить его параметры. Рядом с каждым показано текущее значение, чтобы было видно, какие именно данные покинут дом. «Добавить ещё одно устройство» возвращает к выбору.
- **Настроить группы датчиков целиком** — переключатели «Все измерения», «Все сигнальные датчики», «Розетки и реле», «Освещение», «Сирены», «Краны». Группа охватывает и те сущности, которые появятся позже, и остаётся единственным способом добавить сущности без устройства.

Собственные диагностические сущности интеграции не предлагаются и игнорируются, даже если выбран домен целиком: `sensor.*_очередь_событий` растёт от самой отправки, и подписка на него кормила бы саму себя.

### Дополнительно

| Опция | По умолчанию | Смысл |
|---|---|---|
| Отправлять телеметрию | включено | Числовые значения. Аварии по выбранным сущностям идут всегда |
| Не чаще одной синхронизации в | 60 с | Нижняя граница, а не период: интервал назначает сервер (по умолчанию 300 с) и ниже этого значения не опустится |

### Удалённое управление

Общий рубильник исполнения команд, по умолчанию выключен. Выбор устройств для действий появится здесь вместе с выдачей команд во второй версии сервиса; до тех пор сервер отвечает пустым списком команд.

Настройки применяются сразу: запись перезагружается сама, перезапуск Home Assistant не нужен.

## Сущности

| Сущность | Что показывает |
|---|---|
| `binary_sensor.*_канал_команд` | установлен ли канал команд (SSE) |
| `sensor.*_последняя_синхронизация` | время последней подтверждённой синхронизации |
| `sensor.*_очередь_событий` | сколько событий ждёт отправки; в атрибутах — сколько отброшено |
| `sensor.*_последняя_команда` | статус последней команды и её атрибуты |
| `switch.*_удалённое_управление` | рубильник, доступный из автоматизаций |
| `button.*_проверить_связь` | отправляет тестовое событие немедленно |

## Словарь действий

Облако присылает только имя действия из закрытого списка. `domain` и `service` вычисляет сам агент по типу сопоставленной сущности — из команды они не берутся никогда. Команда с произвольным сервисом (например `shell_command`) отвергается с `unknown_action`, и ни один сервис Home Assistant не вызывается.

| Действие | Роль | Что делает | Требует отдельного разрешения |
|---|---|---|---|
| `close_water` | кран воды | закрывает кран | нет |
| `open_water` | кран воды | открывает кран | **да** |
| `siren_on` | сирена | включает | нет |
| `siren_off` | сирена | выключает | **да** |
| `light_on` / `light_off` | аварийный свет | включает / выключает | нет |
| `request_snapshot` | — | внеочередная отправка полного снимка | нет |
| `ping` | — | проверка канала | нет |

Каждая исполненная команда попадает в логбук с указанием действия, сущности, инициатора и статуса.

Сопоставление ролей и два отдельных разрешения в форме настроек пока не показываются: сервер команды не выдаёт, и настраивать нечего. Сами проверки в агенте написаны и покрыты тестами; экран вернётся вместе с выдачей команд.

## Удалённое управление появится в версии 2

Блок исполнения команд реализован в агенте полностью, но серверная часть выдачи команд выйдет вторым этапом. До этого сервер отвечает пустым списком команд, а `switch.*_удалённое_управление` остаётся выключенным. Это осознанное решение: менять протокол команд после установки у пользователей дороже, чем реализовать его сразу.

## Что происходит при потере связи

События копятся в очереди (до 5000) и переживают перезагрузку Home Assistant. После восстановления связи всё доставляется без дублей. При переполнении отбрасывается только телеметрия — аварии не отбрасываются никогда, а число потерянных сообщается серверу.

Запись очереди на диск отложенная (раз в 10 секунд и только при изменении): Home Assistant часто работает с SD-карты.

## Приватность

- Пароль не сохраняется и не логируется
- До явного выбора сущностей в облако не уходит ничего
- Токены, ключ подписи и e-mail вырезаются из диагностики
- Соединения только исходящие: интеграция не открывает портов и не регистрирует HTTP-обработчиков

## Бренд-иконки

Иконки лежат прямо в интеграции — `custom_components/likehub/brand/` (механизм HA 2026.3+, объявлять в манифесте ничего не нужно). Для версий 2025.1–2026.2 те же файлы подаются отдельным PR в [home-assistant/brands](https://github.com/home-assistant/brands); заготовка и генератор — в `brand/`.

Перерисовать: `python brand/generate_icons.py --variant a --out brand`

## Разработка

```bash
python3.13 -m venv .venv
.venv/bin/pip install pytest-homeassistant-custom-component
.venv/bin/python -m pytest          # 89 тестов, покрытие 89 %
```

CI прогоняет набор на обоих концах поддерживаемого диапазона: Python 3.13 с HA 2025.1 (минимум из манифеста) и Python 3.14 с актуальным ядром, плюс hassfest и HACS action.
